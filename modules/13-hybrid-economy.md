# L5: Гибридная экономика (эмиссия + transaction burn + обязательный relay)

## Проблема zero-sum экономики

Mutual credit система математически zero-sum: если узел A платит X кредитов за relay, relay-узлы получают X. Сумма = 0.

Но если 80% узлов — chatter (отправляют сообщения), а 20% — relay (релеят), то:
- 80% уходят в минус (потребители)
- 20% накапливают плюс (производители)

Это неизбежно в zero-sum системе. Результат: большинство узлов в долгах, экономика нестабильна.

## Решение: гибридная модель

### 1. Инфляция через confirm-N (эмиссия)

Confirm-N даёт НЕ ТОЛЬКО reputation, но и небольшую эмиссию кредитов (как PoW в Bitcoin).

```
Формула эмиссии:
  emission = N * RELAY_CHUNK_SIZE / 1024 * EMISSION_RATE
  
Параметры:
  EMISSION_RATE = 0.1 (10% от relay reward)
  RELAY_CHUNK_SIZE = 512 байт

Пример:
  confirm-2 (2 × 512 байт) → emission = 2 * 0.5 * 0.1 = 0.1 кредит
  confirm-10 (10 × 512 байт) → emission = 10 * 0.5 * 0.1 = 0.5 кредит
```

**Зачем**:
- Создаёт стимул для новичков (можно заработать кредиты с нуля)
- Предотвращает deadlock (когда никто не может отправить, потому что нет кредитов)
- Аналог Bitcoin: майнеры получают новые монеты за работу

### 2. Transaction Burn (сжигание при тратах)

Вместо демереджа (штрафа за хранение) — микросжигание при каждой транзакции.
Это не штрафует relay-узлы за накопление и создаёт предсказуемый механизм
уничтожения денег.

```
BURN_RATE = 0.01 (1% от каждой транзакции)

При отправке:
  cost = hops × KB × SEND_COST
  burned = cost × BURN_RATE           ← сжигается
  to_relays = cost × (1 − BURN_RATE)   ← relay-узлам

Пример:
  Файл 30 KB, 3 hop'а → cost = 90 RELAY
  → 0.9 сжигается (1%)
  → 89.1 получают relay-узлы
```

**Зачем**:
- Не штрафует сбережения (relay-узлы копят кредиты)
- Создаёт предсказуемый механизм уничтожения
- Балансирует эмиссию: emission ≈ burn → стабильность
- Активные пользователи «оплачивают» существование сети

### 3. Обязательный relay для ВСЕХ пользовательских сообщений

Как в Tor: **ВСЕ** сообщения идут через минимум 1 relay, даже если можно напрямую.

```
Правило:
  - Прямые соединения ЗАПРЕЩЕНЫ
  - Минимум 1 relay hop для любого сообщения
  - Это создаёт постоянный спрос на relay-узлы

Зачем:
  - Анонимность (отправитель не знает физического расположения получателя)
  - Равномерное распределение заработка
  - Экономика не замерзает (всегда есть спрос на relay)
```

## Экономическая петля

```
1. Новичок (баланс 0):
   → Отправляет "Привет" через confirm-2
   → Получает: 0.1 кредит (эмиссия) + reputation
   → Баланс: +0.1

2. Через неделю (баланс 5, reputation 3.5):
   → Отправляет фото 5 МБ через 2 relay
   → Платит: 2 * 5000 / 1024 * 1 = 9.77 кредитов
   → Баланс: 5 - 9.77 = -4.77 (в долг, в пределах credit limit = 37.4)

3. Активный relay (баланс 50, reputation 12):
   → Релеит чужие файлы, зарабатывает кредиты
   → Отправляет свои сообщения через relay (платит)
   → Баланс растёт (заработок > траты)

4. Transaction burn сжигает долю трат:
   → Отправитель платит 100 RELAY, 1 сжигается (1%), 99 идёт relay-узлам
   → Активные пользователи «оплачивают» существование сети
```

## Равновесие

```
Эмиссия (confirm-N):
  + создаёт новые кредиты
  + стимулирует новичков
  - может привести к инфляции

Transaction burn:
  + предотвращает инфляцию
  + не штрафует сбережения
  - сжигает часть каждой транзакции

Обязательный relay:
  + создаёт постоянный спрос
  + равномерное распределение
  - увеличивает latency

Баланс:
	Эмиссия ≈ Burn + Траты на relay
  → Стабильная экономика без zero-sum проблемы
```

## Параметры

| Параметр | Значение | Описание |
|---|---|---|
| `EMISSION_RATE` | 0.1 | 10% от relay reward за confirm-N |
| `BURN_RATE` | 0.01 | 1% от каждой транзакции сжигается |
| `MIN_RELAY_HOPS` | 1 | Минимум relay hop'ов для любого сообщения |
| `MAX_RELAY_HOPS` | 3 | Максимум relay hop'ов (для анонимности) |
| `CONFIRM_THRESHOLD` | 2 KB | Максимальный размер для confirm-N (из `11-confirm-n-economy.md`) |

## Adaptive N и emission

Adaptive N из `11-confirm-n-economy.md` сохраняется: если relay-очередь пуста, N=0 и emission=0.
При пустой очереди сообщение отправляется бесплатно — это нормально, сеть не нагружена.

```
N = 0 (пустая очередь) → emission = 0, сообщение бесплатно
N > 0 (есть трафик)     → emission = N × CHUNK_SIZE / 1024 × EMISSION_RATE
```

## Ограничения emission

Emission начисляется ТОЛЬКО при confirm-N в пределах CONFIRM_THRESHOLD (2 KB).
Файлы > 2 KB не получают emission — они используют RELAY credits.

## Сравнение с zero-sum

| Аспект | Zero-sum (старая) | Гибридная (новая) |
|---|---|---|
| Новичок | Не может отправить (нет кредитов) | Может через confirm-N (эмиссия) |
| Баланс | Всегда есть проигравшие | Может быть win-win (эмиссия) |
| Инфляция | Нет | Контролируемая (transaction burn) |
| Спрос на relay | Только при multi-hop | Всегда (обязательный relay) |
| Анонимность | Опциональная | Гарантированная (обязательный relay) |

## Интеграция с симуляцией

```go
// Confirm-N теперь даёт эмиссию
if confirmN > 0 {
    emission := float64(confirmN * cfg.RelayChunkSize) / 1024.0 * cfg.EmissionRate
    from.Balance += emission
    from.EWMAWork += float64(confirmN * cfg.RelayChunkSize)
}

// Обязательный relay: минимум 1 hop
if relayCount == 0 {
    relayCount = 1 // принудительно добавляем relay
    path = addRelayToPath(from, to, online)
}

// Transaction burn при отправке
burn := cost * cfg.BurnRate
from.Balance -= cost
// burn уходит в никуда (не начисляется никому)
```
