# Threat Model & Security 🟡 Required

> **Required.** Без модели угроз защита фрагментарна. Сеть работает, но неизвестно от чего защищаться. Это не «документ для галочки» — это спецификация требований к безопасности.

## Модель угроз

### Атакующие

| Атакующий | Мотивация | Возможности |
|---|---|---|
| **Внешний наблюдатель** | Слежка за трафиком | Мониторинг радиоэфира, глушение |
| **Злонамеренный узел** | Перехват, подмена, отказ в relay | Полный контроль над своим узлом |
| **Sybil-ферма** | Контроль множества узлов для correlation attack | Множество дешёвых узлов |
| **Администрация зоны** | Блокировка сети | Глушение, конфискация оборудования, физический доступ |
| **Bridge-компрометация** | Раскрытие внешних отправителей | Контроль bridge-узла |

### Что защищаем

| Свойство | Описание |
|---|---|
| **Конфиденциальность** | Содержимое сообщений доступно только отправителю и получателю |
| **Анонимность отправителя** | Невозможно определить, кто отправил сообщение |
| **Анонимность получателя** | Невозможно определить, кто получит сообщение |
| **Relationship anonymity** | Невозможно доказать, что A общается с B |
| **Целостность** | Сообщение не может быть изменено в пути |
| **Доступность** | Сеть продолжает работать несмотря на атаки и отказы |

## 1. Конфиденциальность: E2E шифрование

**Угроза**: перехват и чтение сообщений.

**Защита**:
- NaCl box (Curve25519 + XSalsa20-Poly1305) — каждый обмен между пользователями шифруется end-to-end
- Промежуточные relay-узлы не могут расшифровать содержимое
- Даже если злоумышленник контролирует все relay-узлы в цепи — содержимое не раскрывается

```go
// Отправитель
ciphertext := box.Seal(plaintext, recipientPub, senderPriv)

// Получатель
plaintext := box.Open(ciphertext, senderPub, recipientPriv)
```

**Усиление**: Perfect Forward Secrecy через ephemeral ключи для каждой сессии.
Использовать X3DH (как Signal) для начального key exchange.

## 2. Анонимность: Onion routing

**Угроза**: correlation attack (сопоставление входящего и исходящего трафика).

**Защита**:
- **MIN_RELAY_HOPS=1** — минимум 1 relay для любого пользовательского сообщения (чат, файлы, транзакции). Обеспечивает базовую анонимность: отправитель и получатель не видят друг друга напрямую.
- **Рекомендуется 3+ hop'а** для чувствительных сообщений — компрометация 1-2 узлов не раскрывает путь. При 1 hop'е компрометация единственного relay раскрывает связь полностью.
- Служебный трафик (DHT lookup, gossip, ping) идёт напрямую, без relay.
- **Cover traffic ОБЯЗАТЕЛЕН** (Nym-модель, см. `02-onion-routing.md`): каждый узел передаёт с постоянной скоростью (Poisson process). Реальные данные заменяют cover-пакеты в потоке. Loop-пакеты служат liveness check. Без cover traffic пассивный наблюдатель выделяет активных пользователей по наличию трафика.
- **Pool цепей** — отправитель держит несколько готовых цепей, меняет их
- **Padding** — все пакеты фиксированного размера (512/1024/2048 байт)
- **Exponential timing jitter** — случайная задержка с экспоненциальным распределением (макс. энтропия), не uniform

```go
func (n *Node) relayWithJitter(packet []byte, nextHop string) {
    // Exponential jitter: максимальная энтропия тайминга
    meanDelay := 250.0 // мс
    jitter := time.Duration(-math.Log(rand.Float64()) * meanDelay) * time.Millisecond
    time.Sleep(jitter)
    n.transport.Send(nextHop, packet, PriorityRelay)
}
```

## 3. Sybil-атака

**Угроза**: создание тысяч подставных узлов для контроля цепей.

**Защита**:
- **S/Kademlia** — генерация NodeID требует решения криптографического puzzle (PoW)
- **Reputation threshold** — новые узлы с низкой репутацией не выбираются в onion-цепи
- **Возраст узла** — PoH-stream узла доказывает минимальное время его существования
- **Стоимость** — каждый узел требует физического железа (роутер + LoRa модуль)

```go
// Генерация NodeID с PoW (аналогично Hashcash)
func generateNodeID(pubkey [32]byte, difficulty int) (nodeID [32]byte, nonce uint64) {
    for nonce = 0; ; nonce++ {
        hash := sha256(pubkey + uint64ToBytes(nonce))
        if leadingZeroBits(hash) >= difficulty {
            return hash, nonce
        }
    }
}
```

Difficulty = 20 (первые 20 бит нулевые) — ~1M попыток, ~1 секунда на CPU.
Делает массовую генерацию Sybil-узлов затратной.

## 4. Eclipse-атака

**Угроза**: изоляция узла от остальной сети (все соседи — подставные).

**Защита**:
- Узел поддерживает связь с минимум 8 соседями
- Если все соседи дают противоречивую информацию → флаг предупреждения
- LoRa позволяет «слушать» узлы далеко за пределами ближайших соседей
- Периодический broadcast на SF12 для поиска новых соседей

## 5. Denial of Relay

**Угроза**: узел берёт пакет и не релеит (или релеит с задержкой).

**Защита**:
- PoR — получатель relay подписывает квитанцию, relay-узел предъявляет её
- Отсутствие PoR → gossip разносит failure ratio
- Падение reputation → узел не выбирается в цепи
- Экономический стимул: нет relay → нет credits → ограничения

## 6. Replay-атака

**Угроза**: повторная отправка перехваченного пакета.

**Защита**:
- Каждый onion-пакет содержит уникальный nonce
- Узел хранит Bloom-фильтр seen nonce'ов (последние 24 часа)
- Повторный nonce → отбрасываем

```go
func (n *Node) isReplay(nonce [24]byte) bool {
    if n.seenNonces.Test(nonce[:]) {
        return true
    }
    n.seenNonces.Add(nonce[:])
    return false
}
```

## 7. Атака на репутацию

**Угроза**: накрутка reputation через сговор узлов.

**Защита**:
- PoR требует подпись реального получателя relay (нельзя подделать без сговора)
- Gossip reputation — если узел A утверждает, что узел B имеет score 1000,
  но 5 других узлов утверждают score 10 → A теряет доверие
- PoH доказывает время — нельзя "перенести" старую репутацию на новый узел
- Dev налёт на PoH — ваш relay в реальном времени

## 8. Физическая атака

**Угроза**: конфискация оборудования, физический доступ к узлу.

**Защита**:
- Приватные ключи хранятся в зашифрованном виде (парольная фраза при старте)
- При выключении/конфискации — ключи недоступны
- История сообщений шифруется на диске
- Сеть перестраивается без скомпрометированного узла (mesh resilience)
- **Нет центрального сервера** — нечего конфисковывать для остановки всей сети

## 9. Глушение (Jamming)

**Угроза**: RF-глушилка блокирует радиосвязь.

**Защита (многоуровневая)**:
1. **Spread Spectrum (LoRa)** — изначально устойчив к узкополосному глушению
2. **Frequency hopping** — псевдослучайная смена частот по расписанию
3. **Несколько частотных диапазонов** — 433/868/915 МГц + 2.4 ГГц
4. **Ethernet over power** — вообще не радио, глушилка бессильна
5. **DTN** — сообщения хранятся и передаются когда связь появляется
6. **Физические носители** — USB-флешки для передачи больших объёмов

## Резюме: defence in depth

```
Слой 1 — Физический:      Spread spectrum, frequency hopping, ethernet
Слой 2 — Транспортный:    DTN, store-and-forward, адаптивная маршрутизация
Слой 3 — Сетевой:         Onion routing (3+ hop), пул цепей, padding, jitter
Слой 4 — Данные:          E2E NaCl box, PFS, self-certifying names
Слой 5 — Консенсус:       PoR + PoH, S/Kademlia anti-Sybil, gossip reputation
Слой 6 — Экономический:   Mutual credit, тит-фор-тат, стимулы к релею
```
