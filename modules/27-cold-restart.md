# Network Cold Restart 🟡 Required

> **Required.** Без сценария восстановления после массового отключения сеть не вернётся в строй. Cold restart — не гипотетический сценарий, а неизбежность в реальном мире.

## Сценарий

Все N узлов отключены одновременно (отключение электричества, административное
вмешательство). Через некоторое время включаются разом. Что происходит?

## Фазы восстановления

### Фаза 1: Физическое обнаружение (0-5 минут)

```
Каждый узел:
  1. Сканирует WiFi (SSID "RMN-*") и LoRa (JOIN REQUEST на SF12)
  2. Находит соседей → HELLO handshake
  3. Сверяет PoH: "я был жив до tick_X, ты был жив до tick_Y"
  4. Если PoH-потоки не конфликтуют (нет аномального разрыва) → взаимное доверие

Проблема: все узлы имеют PoH age gap (провал во времени).
Решение: age gap ожидаем — все знают что был cold restart.
  → Не penalize за этот конкретный gap
```

### Фаза 2: Peer list восстановление (5-30 минут)

```
1. Узлы обмениваются сохранёнными peer list'ами (из локального кэша)
2. Gossip-лавина: каждый узел рассылает "я онлайн" + свой peer list
3. SNR-based flood suppression ускоряет распространение
4. Через ~log(N) раундов gossip все знают всех

DHT:
  - Сохранён локально на каждом узле (persistent storage)
  - При восстановлении: узлы сверяют XOR-зоны
  - Записи с истекшим TTL удаляются
  - Записи с валидным TTL восстанавливаются
```

### Фаза 3: Репутация и балансы (30 минут — 2 часа)

```
Балансы:
  - Хранятся локально (на узле) → не требуют восстановления
  - Узел помнит свой баланс и предъявляет PoH-доказательство
  
  Проблема: транзакции, которые были в pending на момент отключения.
  Решение: pending TTL продолжает тикать (wall clock).
    Если TTL истёк за время офлайна → отмена.
    Если нет → при восстановлении связи retry.

Репутация:
  - Хранится локально + в DHT (gossip-копии)
  - При восстановлении: узел предъявляет свою версию
  - Соседи сверяют со своими gossip-копиями
  - Если версии расходятся: majority vote (чей снапшот новее по PoH)
```

### Фаза 4: Возобновление relay (2-24 часа)

```
Первые часы после cold restart:
  - Relay-очереди пусты (никто не отправлял сообщения во время офлайна)
  - Dummy-трафик заполняет очереди
  - Первые confirm-N начинают генерировать emission
  - Экономика постепенно разгоняется

Проблема: все узлы одновременно выходят из офлайна.
  → Reputation demurrage применяется за время офлайна (×2)
  → Но все в равных условиях (у всех упала репутация)
  → Относительные веса в relay-выборе сохраняются
```

## Худший случай: только новые узлы

```
Сценарий: все старые узлы уничтожены/конфискованы.
Запускается сеть из 100% новых узлов.

Проблемы:
  1. Нет DHT-копий (новые узлы не хранят старые записи)
  2. Нет репутации (все начинают с 0)
  3. Нет peer list'ов (некому рассказать о соседях)

Решение — bootstrap заново (12-bootstrapping.md):
  1. Физическое обнаружение (WiFi + LoRa)
  2. Постепенное накопление репутации (confirm-N)
  3. SANDBOX → RAMP-UP → ACTIVE (25-node-lifecycle.md)
  4. За 7-30 дней сеть восстанавливается

Это самый медленный сценарий, но он самовосстанавливающийся.
```

## Частичный cold restart

```
Сценарий: 80% узлов отключено, 20% остались онлайн.

Оставшиеся 20%:
  - Продолжают работать как обычно
  - Их DHT-копии актуальны
  - Их репутация не пострадала (были онлайн)

Вернувшиеся 80%:
  - Получают актуальные peer list'ы от оставшихся 20%
  - Gossip быстро восстанавливает топологию
  - Репутация упала (были офлайн) → RAMP-UP

Время восстановления: 5-30 минут (фаза 1-2),
  вместо 7-30 дней полного cold restart.
```

## Параметры

| Параметр | Значение | Описание |
|---|---|---|
| `COLD_RESTART_AGE_GAP_TOLERANCE` | 24 часа | Максимальный PoH age gap без penalty |
| `GOSSIP_RECOVERY_ROUNDS` | log₂(N) + 3 | Раундов gossip для полного восстановления |
| `PENDING_RETRY_AFTER_RESTART` | 5 минут | Задержка перед retry pending после восстановления |
| `DHT_REBUILD_TIMEOUT` | 1 час | Таймаут восстановления DHT из локальных копий |
