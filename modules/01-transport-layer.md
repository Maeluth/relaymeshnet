# L1: Transport Layer 🔴 Core

> **Core.** Без физического и канального уровня сеть не передаёт данные. Wire format, интерфейс транспорта, фрагментация — это протокол.

## Проблема

Связь между узлами должна работать несмотря на:
- Глушение радиочастот (jamming)
- Отсутствие интернета
- Постоянные подключения/отключения узлов
- Географическую разнесённость (разные здания, разные этажи)

## PHYS: Физические каналы

| Канал | Дальность | Пропускная способность | Устойчивость к глушению | Применение |
|---|---|---|---|---|
| **WiFi 2.4/5 GHz** | ~50-100 м | до 100+ Мбит/с | Низкая | Intra-building (комнаты одного этажа) |
| **LoRa 868/915 MHz** | до 10 км | 0.3-50 кбит/с | Высокая (spread spectrum) | Inter-building (между корпусами) |
| **Ethernet over power** | В пределах электросети | до 1 Гбит/с | Абсолютная (не RF) | Backbone внутри здания |
| **Zigbee 2.4 GHz** | ~100 м | 250 кбит/с | Средняя | Альтернатива LoRa внутри здания |

### LoRa: ортогональные Spreading Factor

Ключевое свойство LoRa — сообщения с разными SF на одной частоте не интерферируют:

| SF | Скорость | Дальность | Время в эфире | Назначение |
|---|---|---|---|---|
| SF7 | ~5.5 кбит/с | ~1-2 км | ~50 мс | Соседние узлы, внутри здания |
| SF9 | ~1.8 кбит/с | ~3-5 км | ~150 мс | Между соседними корпусами |
| SF12 | ~0.3 кбит/с | ~10+ км | ~1.5 с | Дальние корпуса, fallback |

Один SX1276 чип в gateway-режиме слушает все SF одновременно. Один физический модуль = несколько логических каналов.

### Frequency Hopping (доп. защита от наблюдателя)

При установленном symmetric link (см. `19-link-verification.md`) два узла
могут синхронизировать псевдослучайную смену частот:

```
1. При HELLO: обмен seed'ом для PRNG
2. Частота меняется каждую секунду: freq = base + PRNG(seed, tick) % 16 × 200kHz
3. Оба узла знают расписание, внешний наблюдатель — нет
4. При потере синхронизации: fallback на общий канал (868.1 МГц), пересинхронизация

Параметры:
  FH_BASE_FREQ = 868.1 МГц (EU) / 915.0 МГц (US)
  FH_HOP_INTERVAL = 1 сек
  FH_CHANNEL_COUNT = 16
  FH_CHANNEL_WIDTH = 200 кГц
```

## LINK: WiFi mesh routing — B.A.T.M.A.N. adv

Для WiFi mesh-сети между узлами используется **B.A.T.M.A.N. advanced**
(batman-adv) — модуль ядра Linux, работающий на уровне L2. Причины выбора:

| Протокол | Уровень | Плюсы | Минусы |
|---|---|---|---|
| **B.A.T.M.A.N. adv** | L2 (Ethernet) | Прозрачен для IP, работает на OpenWRT из коробки, самоорганизуется | Не шифрует (шифрование на L5 onion) |
| OLSR | L3 (IP) | Зрелый, таблицы маршрутизации | Overhead на служебный трафик |
| 802.11s | L2 | Стандарт IEEE | Плохая поддержка в драйверах |

B.A.T.M.A.N. adv выбран потому что:
- Поверх него работает обычный IP → любой TCP/UDP трафик
- Модуль встроен в OpenWRT — не нужно ставить дополнительное ПО
- Каждый узел видит соседей как локальную Ethernet-сеть
- RelayMeshNet работает поверх IP без изменений

**Конфигурация на OpenWRT**:
```
opkg install kmod-batman-adv batctl
batctl if add wlan0
```

Mesh-интерфейс (`bat0`) получает IP из общей подсети (например 10.42.0.0/16).
Поверх этого IP работают все протоколы RelayMeshNet (TCP/WebSocket, DHT, onion).

Транспортный слой оперирует понятием **набора каналов разного качества**, а не одного соединения:

```go
type Channel struct {
    ID       string
    Quality  float64  // 0..1, measured by ACK ratio and RSSI
    Latency  time.Duration
    Bandwidth int64   // bits/sec
    Cost     float64  // энергозатраты на байт
}
```

При отправке транспортный слой выбирает оптимальный канал по метрике:
- **Текстовое сообщение соседу**: WiFi (быстро)
- **Текстовое сообщение в другой корпус**: LoRa SF7 (баланс скорость/дальность)
- **Файл**: разбивается на чанки, параллельно через WiFi + LoRa с striping'ом
- **Fallback**: если SF7 не доходит → пробуем SF9 → SF12

## LINK: Mesh-топология и gossip (SNR-based flood suppression)

Заимствовано из Meshtastic: managed flooding с SNR-приоритетом.

```
При получении broadcast/gossip пакета:
  1. Измерить SNR принятого сигнала
  2. Вычислить backoff = BASE_DELAY / SNR
     → Чем НИЖЕ SNR (дальше узел), тем КОРОЧЕ backoff
     → Дальние узлы ретранслируют ПЕРВЫМИ
  3. Ожидать backoff
  4. Если за время ожидания услышал ретрансляцию от другого узла:
     → Подавить свою (suppress) — сосед уже покрыл эту зону
  5. Иначе: ретранслировать

Результат:
  - Каждая ретрансляция покрывает МАКСИМАЛЬНУЮ новую территорию
  - Минимум дубликатов
  - O(log n) ретрансляций вместо O(n) при обычном flooding
```

### Параметры gossip

```
Было:   Gossip каждые 60 сек, все передают одновременно
Стало:  Gossip каждые 60 сек + случайный exponential jitter (±15 сек)
        + SNR-based backoff при ретрансляции
        + Подавление дубликатов (suppression)
```

## LINK: DTN (Delay Tolerant Networking)

Для LoRa с высокой latency и частыми разрывами:

- Каждый узел имеет очередь исходящих сообщений
- Сообщение в очереди имеет TTL
- При появлении связи с соседом → drain очереди в порядке приоритета
- Store-and-forward: промежуточный узел сохраняет сообщение и передаёт дальше при возможности
- Acknowledgements: end-to-end подтверждение (получатель → отправитель), не hop-by-hop

## Интерфейс транспорта

```go
type Transport interface {
    // Отправить данные конкретному peer
    Send(peerID string, data []byte, priority int) error

    // Broadcast всем соседям
    Broadcast(data []byte, priority int) error

    // Канал входящих сообщений
    Recv() <-chan *Packet

    // Получить список известных соседей с метриками
    Neighbors() []*Neighbor

    // Зарегистрировать колбэк на изменение связности
    OnConnectivityChange(func(peerID string, online bool))
}

type Packet struct {
    From    string    // peerID отправителя (предыдущий hop)
    Data    []byte
    RSSI    int       // уровень сигнала
    Channel string    // по какому каналу пришло (wifi/lora/eth)
}
```

## Аппаратная установка (на будущее)

```
[Роутер OpenWRT] ←Ethernet→ [ESP32 + SX1276 LoRa модуль]
      |
   WiFi AP
      |
[Студент с ноутбуком/телефоном]
```

- Роутер: OpenWRT, запускает RelayMeshNet в режиме host
- ESP32 + LoRa: общается с роутером по serial/UART, обеспечивает LoRa-транспорт
- Студент: подключается к WiFi роутера, открывает WebUI мессенджера
