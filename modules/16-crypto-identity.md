# Crypto & Identity 🟡 Required

> **Required.** Без криптографии нет безопасности. X3DH, Double Ratchet, self-certifying names — это не «фичи», а минимальный набор для сети где любой может быть врагом.

## Identity: кто есть кто в анонимной сети

### Self-sovereign identity

```
PeerID = SHA256(public_key)[0:16]  // первые 16 байт = 32 hex-символа

Свойства:
  - Не требует центра регистрации
  - Невозможно подделать (привязан к ключу)
  - Невозможно украсть (нужен приватный ключ)
  - Не раскрывает личность (просто хэш)
```

### Как Алиса находит Боба

```
1. Out-of-band (первый контакт):
   - QR-код с peerID + pubkey (в WebUI)
   - NFC/Bluetooth обмен
   - Физическая записка

2. DHT-запрос по никнейму:
   - Боб публикует: {nickname, peerID, pubkey, signature, PoH_proof}
   - Алиса ищет: DHT.Get("nickname:bob")
   - Проверяет: peerID == SHA256(pubkey)
   - Проверяет: signature валидна
   - Проверяет: PoH_proof (узел существует минимум N времени)

3. Web of Trust:
   - Алиса доверяет Чарли
   - Чарли доверяет Бобу
   - Алиса → Чарли: "кто такой peerID_X?"
   - Чарли → Алиса: "это Боб, я проверял"
```

### Доверять не доверяя

```
Уровни доверия:
  0. Неизвестный    — peerID виден впервые
  1. DHT-проверен   — peerID + подпись + PoH валидны
  2. Gossip-проверен — N независимых узлов подтверждают reputation > 0
  3. Прямой контакт  — был обмен ключами лично
  4. Relay-проверен  — узел успешно релеил мои пакеты (есть PoR)
  5. Доверенный      — явно добавлен в trusted list

Каждое действие требует минимального уровня доверия:
  - Получить pubkey:     уровень 0
  - Отправить текст:     уровень 1
  - Отправить файл:      уровень 2
  - Перевод RELAY:       уровень 3
  - Открыть сайт:        уровень 1 (read-only)
  - Загрузить на сайт:   уровень 2
```

## Самонакрутка токенов (fake relay)

### Атака
```
Злоумышленник создаёт два узла: A и B.
A «отправляет» 1 ГБ B.
B «релеит» 1 ГБ.
Оба предъявляют PoR квитанции.
→ 2 ГБ × RELAY_REWARD = эмиссия из ничего
```

### Защита: Multi-hop PoR цепочка

```
PoR квитанция требует подписи СЛЕДУЮЩЕГО hop'а в onion-цепи.
Нельзя подписать самому себе.

Для атаки нужно контролировать всю цепь [A→R1→R2→B].
С Sybil-защитой (см. ниже) это дорого.

Дополнительно: статистический анализ
  - Если A и B обмениваются трафиком в 1000× больше чем с остальной сетью → anomaly
  - Gossip разносит anomaly flag → reputation падает
```

### Защита: PoH timestamp

```
PoR содержит PoH-доказательство времени.
Нельзя подделать время — PoH цепочка последовательна.

"Я релеил 1 ГБ в tick_12345" — но если соседи видят что в tick_12345
узел был офлайн → fraud.
```

## Сбор данных (traffic analysis)

### Атака
```
Злоумышленник пассивно слушает радиоэфир.
Видит: кто с кем общается, объёмы трафика, timing.
Даже не расшифровывая, можно построить social graph.
```

### Защита: onion routing (02-onion-routing.md)

```
Каждое сообщение: минимум 3 hop'а для чувствительных данных.
Промежуточный узел знает только: от кого пришло, кому передать.
Не знает: кто отправитель, кто получатель, содержимое.

Padding: все пакеты одного размера (512/1024 байт).
Dummy traffic: фоновый шум маскирует реальную активность.
Timing jitter: случайная задержка 50-500ms перед relay.
```

### Защита: разделение каналов

```
Текстовый чат:       WiFi  (низкая latency, высокий bandwidth)
Файлы:               LoRa  (высокая latency, низкий bandwidth)

Разные типы трафика на разных частотах → сложнее коррелировать.
```

## Подделка сервиса (fake site)

### Атака
```
Злоумышленник регистрирует "students-wiki" в DHT.
Его pubkey отличается от настоящего владельца.
Но ServiceID другой (SHA256(pubkey + name)).
Пользователь видит два "students-wiki" в каталоге.
```

### Защита: self-certifying names

```
ServiceID = SHA256(owner_pubkey + "students-wiki")

Два разных владельца → два разных ServiceID.
Невозможно украсть имя без кражи приватного ключа.

UI показывает:
  students-wiki (0xABCD...01) ★★★★☆ 12 узлов  ← настоящий
  students-wiki (0x1234...FF) ★☆☆☆☆  1 узел   ← подделка

Пользователь выбирает по reputation владельца.
```

### Защита: контентная верификация

```
ServiceRecord содержит хэши статических файлов:
  {"/index.html": "0xAAA...", "/style.css": "0xBBB..."}

Клиент проверяет: скачанный index.html → SHA256 → == 0xAAA ?
Если нет → контент подменён → alert.
```

## Атака на репутацию

### Атака
```
Злоумышленник создаёт 100 Sybil-узлов.
Все 100 голосуют: "узел Bob имеет reputation 0, он мошенник".
Gossip разносит ложную информацию.
```

### Защита: взвешенный gossip

```
Не все голоса равны.
Вес голоса = reputation голосующего × возраст узла.

Новые Sybil-узлы (reputation=0, возраст=0):
  → вес = 0 × 0 = 0
  → их голоса игнорируются

Существующие узлы с reputation > 0:
  → их голоса учитываются
```

### Защита: S/Kademlia Sybil-proof NodeID

```
NodeID = SHA256(pubkey || nonce)
  где nonce подобран так, что первые 20 бит NodeID = 0 (PoW puzzle)

Сложность: ~1M попыток SHA256 (~1 сек CPU).
Создать 100 Sybil-узлов: 100 секунд CPU.
Но главное: NodeID доказывает что узел потратил CPU на генерацию.
Не доказывает честность, но делает массовую генерацию дороже.
```

## E2E шифрование: X3DH + Double Ratchet

### Почему не просто NaCl box

```
NaCl box (Curve25519 + XSalsa20-Poly1305):
  ✓ Одно сообщение
  ✗ Нет Perfect Forward Secrecy (компрометация ключа → расшифровка всей истории)
  ✗ Нет post-compromise security (после компрометации новые сообщения тоже скомпрометированы)
```

### Signal Protocol (X3DH + Double Ratchet)

```
X3DH (Extended Triple Diffie-Hellman):
  Начальный key exchange между Алисой и Бобом.
  Даже если Боб офлайн — Алиса может отправить первое сообщение
  (используя pre-key Боба, опубликованный в DHT).

Double Ratchet:
  Каждое сообщение использует НОВЫЙ ключ.
  Компрометация одного ключа → раскрыто одно сообщение.
  Следующее сообщение — новый ключ, не связанный с предыдущим.
  + Post-compromise security: после компрометации ключи обновляются
    и новые сообщения снова защищены.

Pre-keys:
  Боб публикует набор одноразовых pre-key'ов в DHT.
  Алиса берёт один, использует в X3DH.
  Pre-key удаляется из DHT (использован).
```

## Сводка угроз и защит

| Атака | Защита | Уровень |
|---|---|---|
| **Самонакрутка токенов** | Multi-hop PoR + anomaly detection + PoH | L2/L5 |
| **Сбор данных (пассивный)** | Onion routing + padding + jitter + dummy traffic | L2 |
| **Подделка сервиса** | Self-certifying names + reputation + контентная верификация | L3/L4 |
| **Атака на репутацию** | Weighted gossip + Sybil-proof NodeID | L3/L5 |
| **Перехват сообщений** | E2E X3DH + Double Ratchet | L5 |
| **Корреляция трафика** | Pool цепей + timing jitter + разделение каналов | L2 |
| **Replay атака** | Nonce + Bloom filter | L2 |
| **Physical confiscation** | Зашифрованные ключи + mesh resilience | Все |

## Минимальные требования для разных действий

| Действие | Мин. доверие | Мин. hop'ов | Шифрование |
|---|---|---|---|
| Получить pubkey | 0 | — | — |
| Текст в чат | 1 | 1 | NaCl box |
| Файл < 10 KB | 2 | 2 | NaCl box |
| Файл > 10 KB | 3 | 3 | NaCl box |
| Перевод RELAY | 3 | 3 | X3DH + Double Ratchet |
| Открыть сайт | 1 | 1 | NaCl box (статику) |
| API-запрос к сайту | 2 | 2 | NaCl box |
