# Sovereignty, Clans & Trust Networks 🟡 Required

> **Required.** Без социального слоя сеть — просто набор анонимных узлов. Кланы, суверенитеты, trust bootstrap — это не «фичи», а механизм масштабирования доверия. Без них cold restart занимает недели вместо часов.

## Принцип

RMN не навязывает централизацию. Но и не запрещает добровольные объединения.
Поверх протокольного уровня (алгоритмическое доверие: PoH, PoR, reputation)
строится **социальный слой**: кланы и суверенитеты.

Это не «администрация сети». Это как GitHub-организации: ты сам решаешь вступить.
Как гражданство: ты родился в нём или принял его. Как клуб: платишь взнос — получаешь привилегии.

## Уровни доверия

```
L0: Protocol trust (алгоритмическое)
  → PoH age, PoR receipts, EWMA reputation
  → Есть у ВСЕХ узлов, независимо от принадлежности
  → Медленное накопление (7-30 дней до ACTIVE)

L1: Clan trust (добровольное)
  → Подпись лидера клана на членстве узла
  → Ускоренный ramp-up после cold restart
  → Узлы клана знают друг друга (peer list внутри клана)

L2: Sovereignty trust (наследуемое/принимаемое)
  → Все узлы суверенитета — как части одного целого
  → Максимальное доверие, мгновенное восстановление
  → Суверен (президент) подписывает членство каждого узла
```

## Клан (Clan)

```
Структура:
  - ClanID = SHA256(leader_pubkey + clan_name)
  - Лидер: узел с Ed25519 ключом, подписывает членство
  - Члены: узлы, чьё членство подписано лидером

Вступление:
  1. Узел → Лидер: "хочу в клан"
  2. Лидер проверяет (критерии — на усмотрение лидера: репутация, возраст, личное знакомство)
  3. Лидер → DHT: ClanMembership {node_peerID, clanID, signature, TTL}
  4. Узел получает clan membership — может предъявлять другим членам клана

Преимущества:
  - Cold restart: члены клана узнают друг друга мгновенно (через подписи лидера)
  - Vouch: лидер может поручиться за новичка → ускоренный RAMP-UP
  - Внутренний gossip: члены клана обмениваются reputation быстрее
  - Общий peer list: клан поддерживает список "своих" для быстрого восстановления

Обязанности:
  - Никаких. Членство в клане не накладывает обязательств.
  - Лидер МОЖЕТ установить правила (взнос, минимальный uptime) — но это off-protocol.
```

### Клановый cold restart

```
Без клана:
  Все 500 узлов → BOOTSTRAP → SANDBOX (7 дней) → RAMP-UP (30 дней)

С кланом:
  Узлы клана (50 шт):
    1. Лидер встаёт первым
    2. Члены подключаются, предъявляют ClanMembership (подпись лидера)
    3. Лидер подтверждает: "эти 50 узлов — мои, я за них ручаюсь"
    4. Узлы клана → сразу RAMP-UP (не SANDBOX!)
    5. Внутри клана: полное доверие, relay работает сразу

  Остальные 450 узлов (без клана):
    → Обычный cold restart (7-30 дней)
```

## Суверенитет (Sovereignty)

```
Структура:
  - SovID = SHA256(sovereign_pubkey + sov_name)
  - Суверен (президент): узел с Ed25519 ключом
  - Граждане: узлы, чьё гражданство подписано сувереном
  - Территория: НЕ географическая! Это логическое понятие.
    "Территория суверенитета X" = все узлы, подписанные сувереном X.

Отличие от клана:
  - Клан: добровольное, временное, можно выйти в любой момент
  - Суверенитет: наследуемое/принимаемое, более формальное
  - Суверен может передать власть (подписать преемника)
  - Суверенитет может иметь "конституцию" (правила, зашитые в софт)
```

### Примеры суверенитетов

```
Суверенитет "Campus-Admin" (администрация):
  - 200+ узлов в ключевых точках
  - Официальный сайт, обменник RELAY→рубли
  - Белый список: только граждане этого суверенитета
  - Быстрый cold restart: граждане узнают друг друга через подпись админа

Суверенитет "FreeNet" (независимый):
  - 50+ узлов энтузиастов
  - Никаких списков, открыт для всех
  - Медленный cold restart (нет общего лидера) — но полная анонимность

Суверенитет "StudyGroup-42" (учебная группа):
  - 15 узлов одногруппников
  - Закрытый чат, обмен конспектами, файлообменник
  - Лидер группы подписывает членство
```

## Бан-листы и белые списки

```
Каждый узел может вести свои списки:

Ban list (чёрный список):
  - Забанен peerID → игнорировать все пакеты от него
  - Забанен ClanID → игнорировать всех членов клана
  - Забанен SovID → игнорировать всех граждан суверенитета

Whitelist (белый список):
  - Разрешён ТОЛЬКО peerID из списка
  - Разрешён ТОЛЬКО ClanID из списка
  - Всё остальное → игнорировать

Эти списки — ЛОКАЛЬНЫЕ. Каждый узел решает сам.
Нет глобального бана. Нет "администратора сети".
```

## Три зоны — на одной физической mesh

```
Белая зона (суверенитет администрации):
  - Официальные узлы, обменник, сайты
  - Легально, предсказуемо, поддержка 24/7
  - Но: администрация видит метаданные своих узлов

Серая зона (независимые кланы):
  - Кланы по интересам, учебные группы, файлообмен
  - Частичное доверие, ускоренный cold restart
  - Баланс между анонимностью и удобством

Чёрная зона (полная анонимность):
  - Узлы без кланов и суверенитетов
  - Только протокольное доверие (PoH, PoR)
  - Медленный cold restart, но полная анонимность
  - Невозможно заблокировать на уровне протокола
```

## Почему это не централизация

```
Централизация:              Суверенитет в RMN:
  Один управляет всеми       Каждый решает сам за себя
  Нельзя выйти               Можно выйти в любой момент
  Навязано сверху            Добровольно принято
  Монополия на власть        Множество суверенитетов
  Без вариантов              Можно быть вне любого суверенитета

Суверенитет в RMN — это как выбрать ISP:
  Хочешь — подключись к админскому.
  Хочешь — к независимому.
  Хочешь — вообще без суверенитета, сам по себе.
  Хочешь — создай свой.
```

## Trust Bootstrap: «свои» при первой установке

Genesis-узлы (вшитые в код) несправедливы — они дают преимущество разработчику
на уровне протокола. Вместо этого — **trust list**, настраиваемый владельцем узла
при установке:

```
Новый узел при первом включении → установщик спрашивает:

┌─────────────────────────────────────────────┐
│  Настройка узла                              │
│                                              │
│  Доверенные узлы (peerID или nickname):      │
│  ┌─────────────────────────────────────────┐ │
│  │ maeluth-node-1                          │ │
│  │ maeluth-node-2                          │ │
│  │ friend-alice-node                       │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│  Это твои другие узлы или узлы друзей.       │
│  Им будет больше доверия при холодном        │
│  старте и начальном ramp-up.                 │
│                                              │
│  [Пропустить]  [Сохранить]                   │
└─────────────────────────────────────────────┘
```

### Как это работает

```
Без trust-списка:
  Твой новый узел → SANDBOX (7 дней) → RAMP-UP (30 дней)
  Даже если это твой 50-й узел — он не отличается от вражеского.

С trust-списком:
  Новый узел видит "maeluth-node-1" в trust-списке
  → maeluth-node-1 (TRUSTED, 90+ дней) подтверждает: "это свой"
  → Новый узел: сразу RAMP-UP (не SANDBOX!)
  → Ускоренный рост репутации через vouch от trust-узлов
  
Врагский новый узел:
  → trust-список пуст
  → SANDBOX (7 дней), эмиссия в escrow
  → Никто за него не ручается
```

### Отличие от Genesis

| Genesis (вшито в код) | Trust List (при установке) |
|---|---|
| Одинаково для всех | У каждого свой |
| Навязано разработчиком | Выбрано владельцем |
| Нельзя изменить | Можно редактировать |
| Привилегия разработчика | Личное решение |

Ты не говоришь «я разработчик, доверяй этим узлам». Ты говоришь «я владелец
ЭТОГО узла, вот мои другие узлы, им я доверяю».

## Клановая репутация — видна всем

```
WebUI → Узел → Информация:

  PeerID: 0xABCD...
  Личная репутация: ★★★☆☆ (12.5)
  Клан: "Maeluth-Net" ★★★★★ (89.3)  ← видно всем!

  При холодном старте:
    - Без клана:  SANDBOX (7 дней)
    - С кланом:   RAMP-UP (1 день)   ← ускорено!
```

### Вес в relay-выборе

```
node_weight = personal_reputation × 0.7 + clan_reputation × 0.3

Новичок без клана:    0 × 0.7 +  0 × 0.3 =  0    → SANDBOX
Новичок в клане:      0 × 0.7 + 89 × 0.3 = 26.7  → RAMP-UP (ускорено!)
Ветеран без клана:    50 × 0.7 +  0 × 0.3 = 35   → ACTIVE
Ветеран в клане:      50 × 0.7 + 89 × 0.3 = 61.7 → ACTIVE (приоритет)
```

Личная репутация всегда весомее (70%). Но клановая даёт фору новичкам —
и это справедливо: клан ручается за своих.

### Почему враг не может злоупотребить

```
Враг создаёт клан "TrustedNet" с 50 Sybil-узлами:
  → Клановая репутация = 0 (все 50 узлов — новые, репутации нет)
  → Новичок в этом клане: 0 × 0.7 + 0 × 0.3 = 0
  → Всё равно SANDBOX

Чтобы клановая репутация работала — нужны РЕАЛЬНЫЕ старые узлы.
А их нельзя создать быстро. PoH доказывает возраст.
```

## Параметры

| Параметр | Значение | Описание |
|---|---|---|
| `CLAN_MEMBERSHIP_TTL` | 30 дней | Срок действия подписи лидера |
| `CLAN_MIN_SIZE` | 2 | Минимальный размер клана |
| `SOV_MIN_SIZE` | 10 | Минимальный размер суверенитета |
| `SOV_SUCCESSOR_ENABLED` | true | Суверен может назначить преемника |
| `BAN_PROPAGATION` | false | Баны НЕ распространяются через gossip (локальные) |
| `WHITELIST_MODE` | optional | Белый список — опциональный режим узла |
| `PERSONAL_WEIGHT` | 0.7 | Вес личной репутации в relay-выборе |
| `CLAN_WEIGHT` | 0.3 | Вес клановой репутации в relay-выборе |
| `TRUST_LIST_MAX` | 20 | Максимальное количество узлов в trust-списке |
| `TRUST_VOUCH_THRESHOLD` | TRUSTED | Минимальный статус узла для vouch'а через trust-список |
