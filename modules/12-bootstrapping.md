# Bootstrapping 🟡 Required

> **Required.** Без протокола первого контакта новый узел не может найти соседей. Нет интернета → нет bootstrap-серверов → нужен offline-механизм обнаружения.

## Проблема

Новый узел (только что включённый роутер) не знает ни одного пира.
Нет интернета → нет bootstrap nodes, нет Directory Authorities.
Как найти первый узел и начать обмениваться peer list'ами?

## Этапы bootstrapping'а

### Этап 1: Физическое обнаружение (transport level)

Узел сканирует доступные каналы, ищет соседей:

```
WiFi:  passive scan (слушает beacon frames)
       → видит SSID с префиксом "RMN-*" (RelayMeshNet)
       → подключается к открытой mesh-сети (без пароля, безопасность на L5)

LoRa:  отправляет JOIN REQUEST на общем канале (SF12, частота по умолчанию)
       → ждёт JOIN ACCEPT от любого узла поблизости
       → получает peerID + pubkey ответившего узла

Ethernet: слушает broadcast, ищет RMN-announce пакеты
```

### Этап 2: Криптографическая проверка (trust, но verify)

Получив peerID + pubkey первого соседа:
1. Проверяет: peerID == SHA256(pubkey) — самосертификация
2. Запрашивает peer list соседа (подписанный список известных узлов)
3. Проверяет подписи на peer list
4. НЕ доверяет reputation-значениям из peer list (начинает с нуля)
5. Начинает строить собственную reputation-картину через прямое взаимодействие

### Этап 3: Активная верификация соседа

```
Новый узел → сосед: ping-запрос
Сосед → новый узел: pong-ответ + PoH-доказательство (возраст узла)
Новый узел: проверяет PoH-цепочку → узел существует минимум N часов

Новый узел → сосед: "отрелей этот тестовый пакет мне обратно"
Сосед → ... → новый узел: тестовый пакет вернулся
Новый узел: сосед действительно релеит → начальная reputation +0.1
```

### Этап 4: Gossip-интеграция

Получив peer list, новый узел подключается к нескольким пирам (минимум 3),
обменивается gossip-сообщениями, скачивает DHT-записи для своей XOR-зоны,
начинает полноценную работу.

## Защита от fake bootstrap

| Атака | Защита |
|---|---|
| Поддельный SSID "RMN-*" | Не может релеить трафик → проваливает Этап 3 → исключается |
| Поддельный peer list | Проверка подписей каждого peer в списке; несовпадение pubkey/peerID → отвергается |
| Sybil-окружение (все соседи подставные) | Этап 3 требует реального relay + PoH-доказательство возраста. Создать 8 Sybil-узлов с разными PoH-потоками за разное время — дорого |
| Eclipse (изоляция) | Узел слушает LoRa на всех SF, пытается найти альтернативных соседей. Если все известные соседи дают противоречивую информацию → предупреждение в UI |

## Минимальный bootstrap без WiFi

Если WiFi недоступен (глушилка), а только LoRa:

```
1. LoRa JOIN REQUEST на общем канале (SF12, 868.1 МГц)
2. Любой узел в радиусе слышимости отвечает JOIN ACCEPT
3. Обмен ключами через LoRa (несколько фрагментов)
4. Получение сжатого peer list (топ-20 ближайших узлов)
5. Переход на SF7 для дальнейшего общения

Время bootstrap'а через LoRa SF12: ~2-5 минут
(основная задержка — duty cycle + фрагментация)
```

## Параметры

| Параметр | Значение | Описание |
|---|---|---|
| RMN_SSID_PREFIX | "RMN-" | Префикс SSID для mesh-сети |
| LORA_JOIN_FREQ | 868.1 МГц | Частота для начального JOIN (SF12) |
| LORA_JOIN_TIMEOUT | 120 с | Таймаут ожидания JOIN ACCEPT |
| MIN_INITIAL_PEERS | 3 | Минимум пиров для начала работы |
| BOOTSTRAP_POH_MIN_AGE | 10 мин | Минимальный PoH-возраст соседа для доверия |
